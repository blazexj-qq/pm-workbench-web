# 项目档案模块 · 设计方案（v2 · 含 docx/pdf 解析 + 产值管理）

> 目标：给每个项目建一本"电子底册"——开工参数、**合同（docx/pdf 全文）**、工程量清单都能**存得进、查得出、问得明**，AI 能自动归类量单、能就合同条款答疑、**能统计合同金额与价款并融入产值管理**。
> 本文是设计稿，确认后我再动手写进 `通用项目管理工作台.html`。

---

## 一、这个模块解决什么（大白话）

现在工作台管的是"任务"（进度/质量/安全/风险…），但一个项目开工真正要管的"底册"目前没地方放：

- 这项目建筑面积多大？几栋楼？多高？多少户？合同总价多少？—— 现在散在脑子里或微信里
- 合同里违约金怎么写？工作界面谁和谁划分？**合同金额、付款节点、价款构成**？—— 出事时翻合同 PDF 找半天
- 清单总共有多少量？机电专业占多少？材料计划怎么排？**已干完的活值多少钱（产值）？** —— 全在 Excel，和工作台两张皮

这个模块就是给每个项目加一个**档案页**：基础参数 + 合同 + 量单 + 产值，四块数据打通，AI 帮忙归类、答疑、统计。

## 二、先讲代价（再讲优点，这是规矩）

这个模块要"智能"，离不开 AI。**当前工作台是纯前端单文件（HTML + 浏览器本地库 IndexedDB），没有自己的服务器**。所以：

| 能力 | 怎么实现 | 代价 |
|------|----------|------|
| AI 问答合同 / 自动归计量单 | 复用工作台「设置 → AI 配置」里你填的 API Key（OpenAI 兼容接口） | **要联网 + 每次调用消耗 token（有费用）**；没填 Key 就没有 AI 功能 |
| 合同 / 量单全文存储 | 存在浏览器本地 IndexedDB | **换设备/换浏览器不同步**；除非你已经配了「GitHub 备份」或「飞书同步」 |
| 合同上传 **docx** | 用前端库 **mammoth.js**（约 300KB，CDN 加载）抽取正文 | 纯文本抽取**很可靠**；但只抽文字，不保留排版/表格样式 |
| 合同上传 **pdf（电子版）** | 用前端库 **pdf.js**（约 1MB，CDN 加载）抽取文本层 | **仅"文字版 PDF"能抽**（即电脑导出的那种）；**扫描件/图片型 PDF 抽不出**（需要 OCR，浏览器端基本做不到） |
| 合同上传 **pdf（扫描件）** | ⚠️ 前端无解 | 只能靠：① 你用手机/WORD 先把文字复制出来粘贴；② 或走服务端解析（见替代方案）。**不要指望点一下就自动读出扫描件** |
| 产值统计（金额/完成率） | **纯前端按已存数据算，不耗 AI** | 免费、离线可用；前提是合同金额、量单单价、进度你已经录入了 |

**两条必须如实告诉你的硬限制：**

1. **扫描件 PDF 在网页里读不出文字**。这是浏览器技术天花板，不是我偷懒。工程合同很多是扫描盖章件 → 这类我建议"粘贴文字版"或"服务端解析"。
2. **mammoth / pdf.js 要从 CDN 下载**（联网时自动加载，约 1.3MB）。你用 GitHub Pages 打开没问题；用 `file://` 直接双击打开时，只要电脑联网也能加载，但**断网就抽不了**。

**替代方案（不接 AI、不依赖解析库也能用）：**
- 先把三块数据用结构化表单录进来 + 加一个"全文搜索框"（像 Ctrl+F 搜合同条款）。这步零费用、零依赖，今天就能用。
- 扫描件 PDF：把文字复制粘贴进"合同正文"框（照样能搜、能 AI 问答）。
- 若你**经常**要批量解析扫描件，可加一个**服务端解析函数**（复用你已有的「代理与云端 / 阿里云 FC」模式：网页把文件传上去，服务端用 python 库抽文字返回）。代价 = 多部署维护一个云函数 + 少量调用费。要不要做这步等你定。

> 我的建议：**一期就把 docx + 电子版pdf 上传做进去（用 CDN 库），同时保留"粘贴文字"兜底；扫描件引导粘贴或后续上服务端函数。产值管理一期就上（纯前端算，零成本）。AI 问答/归集作为二期。**

## 三、数据结构设计（给技术参考，看不懂跳过）

在现有 `data.projects[i]`（每个项目）上扩展四个字段，**不动现有任务/进度逻辑**：

```
project.info = {                    // ① 项目基础信息
  buildArea,        // 建筑面积 ㎡
  aboveFloors,      // 地上层数
  belowFloors,      // 地下层数
  height,           // 建筑高度 m
  buildingCount,    // 楼栋数量
  households,       // 规划户数
  structure,        // 结构形式（框剪/剪力墙…）
  contractAmount,   // 合同总金额 万元（也可由 contracts 汇总自动填）
  startDate,        // 开工日期
  planEndDate,      // 计划竣工日期
  remark            // 备注
}

project.contracts = [              // ② 合同（可多份，支持 docx/pdf 上传）
  {
    id, name,                      // 合同名（如"总包合同"）
    type,                          // 类型：总包/分包/采购/其他
    party,                         // 对方单位
    fileName,                      // 原始文件名（如 总包合同.pdf）
    fileType,                      // 'docx' / 'pdf' / 'txt' / 'paste'
    fullText,                      // 合同全文（抽出的纯文本，扫描件为空需手粘）
    amount,                        // 合同金额 万元（录入或 AI 抽）
    priceTerms,                    // 价款条款摘要（付款节点/计价方式/调差…手填或 AI 抽）
    uploadedAt,
    keyClauses:{                   // AI 抽取的关键条款（可选，录后自动填）
      breach,                      // 违约责任
      penalty,                     // 违约金
      interface                    // 工作界面划分
    }
  }
]

project.boq = [                    // ③ 工程量清单（AI 归集后的结构化条目）
  {
    id,
    major,                         // 专业：土建/机电/装饰/幕墙…（AI 打标签）
    category,                      // 分类：如 给排水/电气/通风
    name,                          // 项目名称（如"DN100 镀锌钢管"）
    unit,                          // 单位
    qty,                           // 工程量
    unitPrice,                     // 单价（元，可选）
    amount,                        // 合价（= qty × unitPrice，可选）
    source                         // 来源：'ai' 自动归集 / 'manual' 手填
  }
]

// ④ 智能分析 / 产值管理 —— 不单独存，每次打开实时算：
//    · 合同总额        = sum(contracts.amount) 或 info.contractAmount
//    · 整体进度完成率  = 已完成任务 / 总任务（复用现有进度维度）
//    · 累计完成产值    = 合同总额 × 整体进度完成率
//                       （精算版）= sum(boq.amount，仅统计"对应任务已完成"的条目)
//    · 产值完成率      = 累计完成产值 / 合同总额
//    · 本月产值        = 本期（当月）新增完成产值（按任务完成时间归集）
//    · 材料统计        = 按 boq 的 major + category 汇总 qty
//    · 材料计划        = 按 qty × 交付批次/楼栋粗略排布
```

## 四、录入表单字段清单

### 表单 1：项目基础信息（每个项目一份）
建筑面积(㎡)、地上层数、地下层数、建筑高度(m)、楼栋数量、规划户数、结构形式、**合同总金额(万元)**、开工日期、计划竣工日期、备注。
→ 随时查看、编辑；生成报告时可直接引用这些数字。

### 表单 2：合同录入（支持 docx / pdf / 粘贴）
- 基础：合同名、类型(总包/分包/采购)、对方单位、**合同金额(万元)**、价款条款摘要
- 正文录入（三选一）：
  1. **上传 docx** → mammoth.js 自动抽正文（推荐，最稳）
  2. **上传 pdf（电子版）** → pdf.js 自动抽文本层
  3. **直接粘贴文字** → 扫描件/抽不出的就用这招（兜底，永远能用）
- 录入后点「AI 抽取关键条款」→ 自动填出 违约责任 / 违约金 / 工作界面划分（也可手填）
- 支持多份合同，列表展示，点开看全文 + 搜索 + 提问

### 表单 3：工程量清单录入（两种方式）
- **方式 A（推荐起步）**：结构化逐条录入——专业 / 分类 / 名称 / 单位 / 数量 / 单价
- **方式 B（AI 归集）**：粘贴一大段原始量单文字 → 点「AI 自动归类」→ 输出按专业/分类归好的条目（含单价/合价）→ 你确认后写入

## 五、AI 处理流程（三股流 + 产值）

```
① 合同问答
   用户提问（如"违约金多少？""付款节点怎么约定？"）
     → 取当前项目所有合同 fullText 拼成上下文
     → 调 AI：system="你是工程合同分析助手，只依据给定合同回答，标注条款出处"
             user="基于以下合同回答：<全文>\n问题：<用户问>"
     → 展示答案 + 引用了哪段条款

② 量单归集
   用户粘贴原始量单文本
     → 调 AI：system="把下面工程量按 专业/分类/名称/单位/数量/单价 归类，只输出 JSON 数组"
     → 解析 AI 返回的 JSON → 校验字段 → 写入 project.boq
     → 展示归集结果，用户可删/改/补

③ 智能分析 + 产值管理（纯前端，不耗 AI）
   打开"分析/产值"页
     → 读 project.contracts 汇总 合同总额
     → 读现有进度维度算 整体进度完成率
     → 算 累计完成产值 = 合同总额 × 完成率（精算版用 boq 合价×完成态）
     → 算 产值完成率、本月产值
     → 读 project.boq 按 major/category 汇总 qty（材料统计）
     → 材料计划：按 qty × 交付批次/楼栋粗略排布
```

## 六、工作台交互界面方案

左侧导航新增一项 **「📋 项目档案」**（在现有维度栏下方）。点开后是一个**按项目切换**的档案页，内含 **5 个标签页**：

| Tab | 内容 | 主要操作 |
|-----|------|----------|
| 基础信息 | 项目参数卡片 + 可编辑表单（含合同总额） | 查看 / 编辑 / 引用到报告 |
| 合同 | 合同列表 + **docx/pdf 上传** + 全文查看 + 搜索 + AI 问答 | 新增 / 上传 / 抽条款 / 提问 |
| 量单 | 量单表格 + 归集按钮 + 按专业/分类小计 | 粘贴归集 / 手填 / 增删 |
| 智能分析 | 进度完成率图 + 材料统计表 + 材料计划 | 实时计算、导出 |
| **产值管理** | **合同总额 / 累计完成产值 / 产值完成率 / 本月产值 仪表盘 + 各合同金额对比** | 实时算、引用到报告 |

> 顶部统一有「项目选择器」，切换项目即切换整本档案。报告生成器可直接读取这里的数字（如"本项目建筑面积 X ㎡、合同总额 Y 万元、累计完成产值 Z 万元"）。

## 七、代价与替代方案汇总（决策用）

- **必须配 AI Key 才有的能力**：合同问答、量单自动归集、关键条款抽取。费用 = 各家 API 按 token 计价，单次提问约几分钱量级（取决于合同长度）。
- **零成本立刻能用**：结构化录入 + 全文搜索 + 智能分析 + **产值管理**（进度/材料/金额统计全是纯前端算）。
- **docx/pdf 解析代价**：要联网加载 mammoth/pdf.js（约 1.3MB）；**电子版 PDF 和 docx 能抽，扫描件 PDF 抽不出**（需粘贴或服务端函数）。
- **存储局限**：数据存在当前浏览器；多设备同步靠你已配的 GitHub 备份 / 飞书同步。
- **扫描件大量出现时**：可加「服务端解析函数」（阿里云 FC 模式），代价是多维护一个云函数。
