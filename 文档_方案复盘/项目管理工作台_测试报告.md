## 三、核心计算逻辑验证（关键，因涉及钱数）

逐项用边界数据验证，全部正确：

- **合同总额 `contractTotal`**：合同数组求和；无合同时回退 `info.contractAmount`；空时为 0。
- **整体完成率 `overallCompletion`**：正确过滤"仅本项目 + progress 维度"，排除其他维度/项目。
- **产值 `outputValue`**：`合同总额 × 完成率`，完成率 0 时产值 0、比率 `'0.0'`（字符串，非 NaN）。
- **量单透视 `boqPivot`**：按"专业 × 费用组成"聚合；缺省归"未分专业/综合"；支持 `qty×unitPrice` 推算金额。
- **按完成时间归集 `timeAccruedOutput`**：按进度任务数量均摊，已完成任务按 `completedDate` 月份累计；未填日期进 `__undated` 桶；最终累计值 = `outputValue.done`（内部自洽）。
- **付款阶段判定 `detectPayPhase`**：依据工期节点类型/名称命中 结算→验收→完工→进度，逻辑正确。
- **可申请支付 `payableInfo`**：进度 75% / 完工 80% / 验收 90% / 结算 95% / 保修金 100%，各阶段累计与增量计算正确；保修金残值 = `100−结算比例`（默认 5%）；自定义比例生效。
- **工期状态 `msStatus`**：实际≤计划=已完成；实际>计划=延期；无计划=正常；临期(≤3天)/逾期判定正确。
- **累计曲线 `accrualChartSVG`**：有数据返回合法 SVG，无数据返回空串。

## 五、缺陷与观察（按严重度）

### 🟢 严重 / 崩溃级 Bug：**0 个**
> 本次未检出会导致页面崩溃、白屏、计算错误的功能性缺陷。此前多轮修复（白屏、反引号奇偶、版本守卫、对象拼接 `[object Object]`）已生效。

### 🟡 设计级观察（非崩溃，建议知悉）

1. **合同金额"双入口"互斥（低）**：`合同总额` 同时可由「基础信息 `contractAmount`」和「合同列表各 `amount`」两处录入，但 `contractTotal` 只认**合同列表求和**；若两者都填，基础信息里的值会被忽略（仅当合同列表为空或求和恰好为 0 时才回退到基础信息）。建议：界面上标明"以合同列表为准"，或把基础信息合同额改为只读汇总。
2. **专业产值表口径受限（低）**：「产值管理 → 各专业产值」只展示**在进度任务里出现过 `major` 专业**的量单合价；若某量单专业在进度任务中无对应条目，该专业金额不会出现在"专业产值"表里（但仍出现在"价款分类汇总"透视里）。属数据关联口径问题，不影响数值正确性。
3. **扫描件 PDF 无法浏览器内解析（已知、设计取舍）**：电子版 PDF/docx 可由 mammoth.js / pdf.js 解析；**扫描件/图片型 PDF 解析不出文字**，代码已有"复制文字粘贴"兜底，不崩。
4. **数据存本地浏览器（已知）**：IndexedDB 按 origin 隔离（`file://` / localhost / GitHub Pages 各自独立），换设备/清缓存不同步；需靠 GitHub 备份或飞书同步搬运。

### 🔵 未覆盖项（测试局限，非缺陷）
- 真实浏览器 DOM 渲染、IndexedDB 持久化与跨视图数据流。
- AI 调用链路（`askContract` / `aiExtractClauses` / `aiSortBoqRun` / `msAiParseRun`）仅验证底层函数已定义，**未实际发起请求**（需真实 AI Key + 联网）。
- docx/pdf 真实文件解析（需浏览器 + CDN 加载解析库）。
