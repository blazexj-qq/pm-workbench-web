# 通用项目管理工作台 · UI/UX 优化改进意见（资深 UI 工程师视角）

> 评审对象：`项目管理工作台/通用项目管理工作台.html`（v2026-08-04-09-30 基线，含随手记+语音+GitHub 备份）
> 评审人：阿默（戴资深 UI 工程师帽子）
> 评审日期：2026-08-05
> 目标用户画像：非 IT 背景的机电项目 PM，主要在桌面双击使用，偶尔 iPad/手机打开；最怕「看着乱、不会用、录入麻烦」。

---

## 一、总体评价（先讲好的，避免只挑刺）

这套单文件 HTML 的地基其实相当扎实，很多个人工具做不到：

- ✅ **有统一设计令牌**：`:root` 里 `--accent/--ok/--warn/--bad/--line` 一整套 CSS 变量，改主题只改一处。
- ✅ **有渲染错误兜底**：`render()` 包了 try/catch，渲染崩了显示红框而不是白屏（第 859–868 行）。
- ✅ **有 toast 轻提示**：`toast()` 存在，随手记/模板都有「已记录 ✓」反馈（第 1449 行起）。
- ✅ **有 AI 加载态**：`aiRun` 会显示「AI 处理中」占位（第 1750 行）。
- ✅ **有空状态**：多个视图区分了「暂无数据 / 暂无项目」等占位文案。
- ✅ **响应式起点**：`@media(max-width:820px)` 把侧栏改成抽屉（第 236 行起）。
- ✅ **录入减负已做**：随手记一句话建任务 + 5 模板 + 语音，正是「防放弃」的正确方向。

**一句话**：功能完整度 80 分，但「打磨度」只有 55 分——下面这些才是拉开专业工具和业余工具差距的地方。

## 二、优先级框架

按「影响正确性 / 影响非 IT 用户上手 / 改造成本」三维度排序。
**P0 = 必须修（不改会出真问题）；P1 = 强烈建议（体验跃升、成本小）；P2 = 锦上添花。**

## 三、P0 · 必须修

### P0-1 移动端 / iPad 左侧永久留白 bug（真实可用性问题）
- **现象**：`.main{margin-left:230px}` 是无条件写的（第 77 行）。在 `max-width:820px` 断点里，侧栏变成了 `translateX(-100%)` 收起，但 `.main` 的 230px 左边距**没被重置**。
- **后果**：在手机 / iPad 窄屏上，内容区左边永远空出 230px，右边被挤窄，文字换行很难看。
- **改法**：在 `@media(max-width:820px)` 块里加一句 `.main{margin-left:0;padding:14px}`。
- **代价**：1 行 CSS，零风险。**这是性价比最高的一改。**

### P0-2 导航版本号过期，且会误导用户
- **现象**：侧栏底部写死 `v2026-08-04 09:30 · 新增会议纪要模块`（第 508 行），`<meta app-version>` 也是旧值（第 10 行）。但我们后来往这个文件加了**随手记 + 语音 + GitHub 面板**，版本号没更新。
- **后果**：你前两天刚因为「界面跟昨天不一样」焦虑过。一个写死的旧版本号，会让老徐每次打开都怀疑「这是不是旧版？」。而且现在「检测旧版本」的防御逻辑（第 11–53 行）依赖这个 meta——meta 和文件实际内容对不上，反而制造混乱。
- **改法**：每次大改手动更新这两处；或干脆把版本号从「功能名」改成「日期戳」，并在顶部加一行「最近更新：2026-08-05 新增随手记/语音」。
- **代价**：手动维护，2 分钟。

## 四、P1 · 强烈建议（对非 IT 用户上手最关键）

### P1-1 首次使用引导（空状态 Welcome）—— 对他这种用户价值最高
- **为什么**：老徐是非 IT 用户，打开一个 9 视图 + 11 维度的密集中文仪表盘，第一反应是「这啥、从哪点」。没有 onboarding，再好的功能也白搭。
- **改法**：数据为空时，驾驶舱不显示空图表，而是显示一张「🚀 3 步开始」引导卡：
  1. 点「＋ 新建任务」或顶部「💡 随手记」记第一条
  2. 去「设置 / 备份」填 GitHub Token 防丢
  3. 试试「会议纪要」粘贴一段纪要自动拆任务
- **代价**：纯前端一个条件渲染分支，半天工作量。收益最大。

### P1-2 信息架构重组（汇报类归拢，减少「这俩啥区别」）
- **现状**：9 个导航项是 `总览 / 任务台账 / [11维度] / 会议纪要 / AI助手 / 工作汇总 / 工作笔记 / 自动化规则 / 设置`。
  - 「会议纪要」孤零零放在「会议 & 汇报」组，但「工作汇总」（也是汇报产出）却被丢在「智能 & 系统」组；
  - 「工作笔记」「会议纪要」「工作汇总」「AI 助手」四个名字相近，非 IT 用户容易懵。
- **改法**：
  - 把 **工作汇总** 挪到「会议 & 汇报」组（都是产出物）；
  - 给每组加一行**一句话说明**，例如「工作笔记=随手记想法 / 会议纪要=开会记录 / 工作汇总=生成周报月报」。
- **代价**：改导航分组 + 加说明文字，1 小时。**纯信息整理，不改功能。**

### P1-3 维度排序在触屏（iPad）上完全不可用
- **现状**：维度排序用 HTML5 拖拽 `draggable="true"`（第 812–822 行）。拖拽在触屏（iPad Safari）**根本不触发**，键盘也操作不了。
- **后果**：如果你在 iPad 上用工作台，永远没法调整维度顺序。
- **改法**：每个维度项右侧加「↑ ↓」两个小按钮（或长按弹出菜单），触屏/键盘都能排。
- **代价**：加两个按钮 + 复用 `reorderDim()`，约 1 小时。

### P1-4 统一空状态组件
- **现状**：空状态写法不统一——有的用 `.muted` 内联（第 986、1077 行），有的用带图标的 `.notes-empty`（第 169 行）。风格割裂。
- **改法**：抽一个 `emptyState(icon, text, actionBtn)` 函数，全站复用，保证「图标 + 文案 + 可选操作按钮」三件套一致。
- **代价**：小重构，2 小时，纯体验一致性。

## 五、P2 · 锦上添花

### P2-1 暗色模式切换（内容区）
- 侧栏是深色，但内容区强制浅色。`:root` 里 `--bg:#0d1117` 定义了却没用上（body 用 `--soft` 浅灰）。
- 给「设置」加一个「🌙 暗色模式」开关，切换 `--bg/--card/--ink` 一套变量即可。夜间看报表更护眼。
- **代价**：定义两套变量 + 一个 toggle，半天。注意表格/标签在暗色下的对比度要重测。

### P2-2 快捷键 / 命令面板（⌘K）
- 9 导航 + 11 维度 = 20 个点击目标，纯鼠标效率低。加一个 `Ctrl/⌘+K` 命令面板，输入「周报」直接跳工作汇总。
- **代价**：中等，需自建一个浮层 + 模糊搜索，1–2 天。桌面重度用户才用得上。

### P2-3 键盘可达性 & 焦点可见
- 目前只有笔记 textarea 有 `:focus` 高亮（第 133 行）。Tab 键游走时其他按钮/输入框没有可见焦点环。
- 加全局 `:focus-visible{outline:2px solid var(--accent);outline-offset:2px}`，并让弹窗打开时焦点自动进第一个输入框。
- **代价**：几行 CSS + 少量 JS，1 小时。顺带提升无障碍合规。

### P2-4 视觉一致性收敛
- 内容区散落多种渐变：简报卡琥珀渐变、AI 区蓝渐变、提示蓝渐变、语音按钮紫渐变。多则乱。
- 建议收敛成「主色蓝 + 1 个强调渐变（紫，仅用于 AI/语音）」，其余用纯色描边卡片。
- **代价**：审美层面的收束，需你拍板风格，半天。

### P2-5 渲染策略（innerHTML 全量重渲的副作用）
- 每次切视图都 `v.innerHTML = renderXxx()` 整段替换。代价：切走会丢失当前滚动位置、输入框焦点、筛选框已输入内容。
- 对个人小数据量影响不大，但若以后做「筛选中途切视图再切回」会恼火。
- **代价**：要引入局部更新或状态保留，属架构级改动，2–3 天，**非必要先不动**。

## 六、小 bug 清单（顺手修）

| 位置 | 问题 | 修法 |
|---|---|---|
| 第 199 行 `.tag{...font-size:.8;}` | `font-size:.8` 缺单位（应为 `.8rem`），浏览器会忽略该值 | 改为 `.8rem` |

## 七、实施建议（分阶段，先 P0 后 P1）

1. **本周（30 分钟）**：P0-1 + P0-2 + 小 bug（都是 1 行级改动，关掉旧标签页强刷即见效）。
2. **下周（半天～1 天）**：P1-1 首次引导 + P1-2 导航分组说明 + P1-4 空状态统一。这三件对非 IT 用户「愿意用下去」最关键。
3. **有余力再做**：P1-3 触屏排序、P2 系列。

> 设计原则（呼应老徐定的规矩）：**先讲代价再讲优点**。上面每条都标了「代价」——P0 几乎零代价必做；P1 是小投入大体验；P2 是持有成本更高的「锦上添花」，按需再上，别为了好看堆功能。

---

## 八、我的总体判断

这款产品**功能密度已经超过多数同类个人工具**，短板不在「能不能做」，而在「非 IT 用户敢不敢用、用得顺不顺」。
最该优先投入的不是加新功能，而是 **P0 修 bug + P1-1 首次引导 + P1-2 说人话的导航**——这三件做完，老徐打开就不会再问「界面怎么跟昨天不一样 / 这俩有啥区别」了。
